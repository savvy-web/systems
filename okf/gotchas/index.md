# Gotcha

* [A green bundle followed by EISDIR from inside API Extractor's SourceMapper is a declaration-map segment with no source, not a filesystem problem](sourceless-declaration-map-segments.md) - rolldown 1.2.15+ writes source-less (1-field) mapping segments into .d.ts.map for declarations TypeScript synthesizes with no source position — the hoisted \`declare const X\_base\` behind a class whose heritage clause is a call expression; API Extractor's SourceMapper resolves such a segment to the .d.ts's own directory and readFiles it, so the meta pass dies with EISDIR. generateMeta scrubs those segments before every run.
* [A patch-level bundler bump that adds ae-forgotten-export errors is TypeScript 7.1 emitting typeof references, not a bundler regression](tsgo-typeof-forgotten-export.md) - Since @savvy-web/tsdown-plugins 2.11.0 declarations come from TypeScript 7.1 (tsgo), which emits any exported member whose value is a bare reference to a non-exported module-level binding (a class static such as static readonly x = x, an object-literal property, or a member of an Object.assign statics object) as a typeof reference to that binding where TypeScript 6 inlined its signature; API Extractor then reports ae-forgotten-export for each one with no source change. The fix is in the consumer's source, site by site (inline, static method, or annotation), not the build pipeline.
* [A public-hoisted workspace package resolves to its source tree, not its built artifact](hoisted-workspace-package-resolves-source.md) - Hoisting a workspace package via publicHoistPattern symlinks the package's source directory and ignores publishConfig.directory, so a tool that resolves it by id loads raw TypeScript through Node's type-stripping and looks like it works.
* [The @effect/platform-node root import needs redis, and only Yarn 1 shows it](platform-node-root-import-requires-redis.md) - Importing the root @effect/platform-node entry evaluates NodeRedis, which imports its required redis peer; npm, pnpm and bun auto-install that peer, so a shipped bin works everywhere except under Yarn 1, which fails with ERR\_MODULE\_NOT\_FOUND 'redis'. Shipped code imports platform-node by subpath.
* [The it2 dogfood doorbell's --retry delivers the notice several times](it2-doorbell-retry-duplicates.md) - it2 session send-text --retry 3 reports 'Text not delivered' against a Claude Code session even when the text landed, so the dogfood doorbell types the same notice into the counterpart up to four times while reporting success only on the last attempt (savvy-web/systems#755, open).
* [The repo-wide build ignore rule hides the plugin's build skill while build --check stays green](gitignore-build-rule-hides-plugin-build-skill.md) - The root .gitignore ignores every directory named build, which includes the silk plugin's build skill in plugin/ and in both committed builds; pluginfinity build --check compares files on disk, so it passes while git tracks none of them and the merged plugin ships without the skill.
* [The tsgo generator fails with "No TypeScript Go project found" when the dts-emit tsconfig does not describe the package's files canonically](tsgo-project-membership.md) - rolldown-plugin-dts's tsgo generator opens the temp-dir dts tsconfig as a TypeScript project and looks each entry up by realpath'd module id, so a symlinked package dir or a base tsconfig with no include makes every entry look like it is outside the project; writeDtsEmitTsconfig restates the base canonically to prevent it.
* [markdownlint --fix renumbers a list split by a column-0 host-block marker](markdownlint-fix-renumbers-host-block-lists.md) - A pluginfinity host-block marker at column 0 inside an ordered list ends the list, so the pre-commit markdownlint --fix pass renumbers the following items and dedents their sub-bullets; the skill still builds and reads fine until the rendered numbering is compared with the original.
* [pkill on a monitor script name kills every session's monitor](pkill-monitor-kills-every-session.md) - Every Claude Code session runs its own copy of the silk monitors from the same plugin path, so pkill -f watch-issues.mjs (or any monitor file name) stops the monitor in every open session, not just the one being debugged, and the others go quiet without saying so.
