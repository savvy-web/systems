# Decision

* [An Effect-native MCP server](effect-native-mcp-server.md) - @savvy-web/mcp runs on effect/unstable/ai's McpServer instead of the @modelcontextprotocol/sdk, registering its toolkit through @effected/mcp's McpToolkit so every success is the typed result in structuredContent with the same object as JSON in content\[0\].text.
* [Build each workspace-dependency package via its own prepare script](per-package-prepare-builds.md) - Every package another manifest depends on as workspace:\* carries its own prepare script (turbo run build:dev) instead of relying on a root prepare or turbo's dependsOn.
* [Carrier-pattern package graph](carrier-pattern-package-graph.md) - @savvy-web/silk carries the savvy/savvy-mcp bins as ordinary bin entries over the front ends' ./main contract, replacing a pnpm-only publicHoistPattern that only ever worked for one package manager.
* [Deny Biome by whether the command reaches the binary, not by script name](biome-deny-by-binary-not-script-name.md) - biome-direct-deny denies a command only when it syntactically reduces to the Biome binary itself; it never inspects or denies a package-manager script by name, since a script always resolves package.json (and therefore the repo's Biome config) before anything runs.
* [Enforce vendored-repo read-only via OS permissions, not guards alone](vendored-repos-lockdown.md) - Repos.ReposLockdown chmods vendored worktrees read-only as the actual boundary; the plugin's Bash/fs/MCP guards are early-warning UX in front of it, not a substitute for it.
* [Every package versions independently](independent-package-versioning.md) - \`.changeset/config.json\` declares no fixed or linked groups; every one of the twelve published packages, including former linked groups, cuts its own release, with changesets auto-bumping dependents and npm-registry-only release posture where that applies.
* [Kit Effect peers supplied via the effected catalog](kit-effect-peers-via-catalog.md) - silk-core and silk-effects declare only the identity-carrying @effected/\* packages (commands, git, templates, workspaces) as required peers, spelled catalog:effected:peers, with ranges supplied by @effected/pnpm-plugin-effect's catalogs rather than hand-pinned versions.
* [Pin typescript to ^6.0.3 in tsdown-plugins for declaration emission](typescript-6-dts-pin.md) - @savvy-web/tsdown-plugins pins typescript ^6.0.3 directly (not catalog:silk) and forces dts.generator: tsc, because TypeScript \>=7 has no stable compiler API until 7.1 and flips rolldown-plugin-dts to a generator that breaks emit.
* [Split the build orchestrator from the plugin pack](bundler-tsdown-plugins-split.md) - @savvy-web/bundler and @savvy-web/tsdown-plugins are two packages, split on an interface boundary, rather than one build-tool package.
* [The savvy front ends adopt the effected front-end kit](front-ends-adopt-effected-kit.md) - @savvy-web/cli, @savvy-web/mcp and silk's carrier shims run on @effected/engine, @effected/cli and @effected/mcp, and the layering and source-boundary guards on @effected/workspaces/testing, in place of process wiring this repository hand-rolled; mcp registers its toolkit through McpToolkit, the mcp crash guards are kept, and cli results move to a local Output helper on stdout.
* [silk pins siblings as dependencies, never peers](silk-pins-siblings-as-dependencies.md) - @savvy-web/silk declares cli, mcp, changelog, and silk-effects as exact-pinned regular dependencies rather than peerDependencies, because publishing them as peers made pnpm's autoInstallPeers propagate their Effect graph into consumers at the wrong version.
