# CSH003 — changeset-content-structure

Validates content quality within changeset sections.

## What it checks

- **No empty sections.** An h2 heading followed immediately by another h2 (or
  the end of the file) has no content. Every section must describe at least
  one change.
- **Code fence language.** Fenced code blocks must declare a language
  identifier (e.g. `ts`, `json`, `bash`) so rendered changelogs get syntax
  highlighting.
- **No empty list items.** A bare `-` with no text is flagged.

## Why

An empty section or list item renders as noise in the changelog, and an
unlabeled code fence loses highlighting in release notes.

## Bad

````markdown
## Features

## Bug Fixes

- Fixed crash
-

```
const x = 1;
```
````

## Good

````markdown
## Bug Fixes

- Fixed crash on startup

```ts
const x = 1;
```
````
