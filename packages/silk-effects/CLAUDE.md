# @savvy-web/silk-effects

Shared Effect library for the Silk Suite, and the home of the dev-tooling business logic consumed by `cli`, `mcp`, and `silk`. Single root export, dual-format ESM+CJS.

## Key surface

- One entry point (`.`) exporting five namespaces — `Changesets`, `Commitlint`, `Lint`, `Turbo`, `Repos` — plus standalone services, schemas, and tagged errors.
- `Turbo` is a read-only Turborepo inspection namespace: `TurboInspector` service (needs `ToolDiscovery` from `@effected/commands`) + `TurboDigest` pure transforms (`diagnoseCache`/`taskGraph`/`affected`), all `--dry`, never executes tasks.
- `Repos` owns the vendored `.repos/` mechanism through four services: `ReposConfigStore` (the `.repos/config.json` manifest; every mutation goes through its lock-serialized `update`), `ReposManager` (`status`/`sync`/`add`/`pin`/`note`/`remove`/`rename`/`restore` submodule plumbing over `@effected/git`), `ReposDrift` (read-only `check`, reconciling FIVE authorities into TEN drift kinds behind `savvy repos status --drift`) and `ReposLockdown` (the boundary). Load the design doc before changing any of it; these invariants must not be broken blind:
  - **The lock covers the WORKTREE only** — files `0444` / dirs `0555`, each file's executable bit preserved, symlinks skipped entirely (no `lchmod` on Linux). The submodule's git metadata dir is deliberately NOT locked: a read-only gitdir breaks `git pull`'s default submodule recursion (it cannot write `FETCH_HEAD`) and any client keeping per-gitdir state (GitKraken's `gk/`). `walkRoot` is ASYMMETRIC ON PURPOSE and the asymmetry IS the migration — `unlock` still walks the gitdir (freeing one an older version locked), `lock` never re-locks it, so one `savvy repos sync` migrates a checkout. Do not "fix" that.
  - The worktree lock blocks file edits and `git reset --hard` but NOT `git checkout <other>` (verified, git 2.54), so the invariant is "a drifted pin is always detected and one command from repaired" (`checkoutDiverged` → `restore`), NOT "the pin cannot drift".
  - **The declarative half is written by BOTH `sync` and `add`**: `submodule.<path>.update = none` and `fetch.recurseSubmodules = false` into the superproject's LOCAL config, never `.gitmodules`. `update = none` also makes `git submodule update --init` skip, so `sync` flips the key to `checkout` around its own git work (`@effected/git`'s `submoduleUpdate` exposes no `--checkout`); `add` needs no flip. Never set `active = false` — an inactive submodule reads as uninitialized, so drift would report `missingWorktree` for every repo, and `git submodule init` flips it back anyway.
  - The permissions are the boundary; the silk plugin's Bash/fs/MCP guards are early-warning UX in front of them, never a substitute. A hand `chmod` survives only until the next `sync`/`pin`/`restore`. Reads work unmodified against a locked tree.
  - `sync`/`add`/`pin`/`remove`/`restore` bracket their git mutations in `withUnlocked`, which owns the whole relock finalizer contract (a relock failure surfaces as `ReposLockdownError` only when it is the SOLE failure); `rename` hand-rolls the same contract because it unlocks `oldName` and must relock `newName`. Lock recursion order is direction-dependent (lock chmods a dir AFTER recursing, unlock BEFORE) — inverting it fails with `EACCES`.
  - Reports state what was ACHIEVED, not attempted: `ReposSyncReport.boundaryMarked`, `ReposRestoreResult.stillDirty` (`restore` re-reads `git status` after the reset), `ReposRemoveResult.removedEntry` — hand its `orientation` back to `add`'s `orientation` option to make a re-vendor lossless. `sync`/`restore` deinit a vendored repo's own submodules first, since sparse-checkout cannot evict a nested checkout. The deprecated `RepoStatusEntry.commit` alias is GONE; read `stagedCommit`.
  - Every `manifest.repos[name]` membership read goes through the `Object.hasOwn`-guarded `getRepoEntry` helper, never a bare bracket read — a manifest key literally named `"constructor"` must fail typed as `RepoNotFoundError`.
- `Changesets` holds `ConfigInspector`, `BranchAnalyzer`, `ChangesetLinter`, `ReleasePlanner` and `DepsRegen`.
- `ReleasePlanner` (`plan`/`preview`/`apply`) drives the changesets v3 engine directly — no v1 packages adapter, and `apply` does native, dry-run-aware version bumping. `preview` and `apply` both take a `changelogModules` option mapping changelog ids to module paths for no-`node_modules` callers, sharing one `withChangelogModules` rewrite; `plan` renders nothing so it needs none. Map membership is `Object.hasOwn`, NEVER `map[id] === undefined` — an id naming an `Object.prototype` member reads back an inherited function through the latter and skips the typed unmapped-id error.
- `DepsRegen` splits `plan`/`execute` and owns dependency-changeset orchestration. It snapshots both diff sides via `@effected/workspaces`' `WorkspaceSnapshots` (the kit renamed this from `PointInTimeWorkspace` — that name is gone, do not reintroduce it), resolving `catalog:`/`workspace:` per ref BEFORE diffing so equal-resolved rows are suppressed, and drops `devDependency` rows. Gating is "versionable minus ignored" — in scope when `publishable OR privatePackages.version` AND not on the changeset ignore list (ignore wins over `--package`). A pure dependency changeset is deleted ONLY when its package is in scope AND rewritten this run (present in `toWrite`) AND the file was authored on this branch rather than already committed at the merge-base ref (`gitListChangesetFilesAtRef`) — either gap destroys a still-relevant release note with nothing recreated (#258). `plan()` refreshes `ConfigInspector` and `ChangesetConfig` first, because both hold per-root caches that never self-expire and a long-lived host (the `savvy-mcp` server keeps one `DepsRegen` per process) would otherwise miss `.changeset/config.json` edits between calls (#229). File I/O runs through `FileSystem` (`ChangesetIOError`). `DepsRegen.layer` requires `WorkspaceSnapshots | ConfigInspector | WorkspaceDiscovery | PublishabilityDetector | ChangesetConfig | Git | FileSystem`; `DepsRegenDefault` supplies silk's opinionated defaults and leaves only `FileSystem | Path | ChildProcessSpawner` open — `WorkspaceSnapshots` reads git history, so give it a spawn-capable platform layer (`NodeServices.layer`), never a filesystem-only one.
- `ConfigInspector` file attribution has a fixed precedence: (1) directory containment, deepest `workspaceDir` wins; (2) `additionalScopes`; (3) `versionFiles`; (4) a root-as-package fallback. A scope whose `workspaceDir` IS the project dir is held OUT of the containment pass and applied only at step 4 — every file is "inside" the root by definition, so competing on containment let it shadow the `additionalScopes`/`versionFiles` a config declared. Keep that ordering when touching `classifyOne`. Step 4 stays containment-checked, so a `../` or absolute path outside the repo stays unmapped. Its release-surface fallback treats EVERY workspace package as a release surface when the config sets `privatePackages.version: true`, per the `ChangesetConfig.versionPrivate` truth-table.
- `ChangesetLinter.validateContent` now enforces the dependency-table format (CSH005) via the remark `DependencyTableFormatRule`; prose `## Dependencies` sections are rejected.
- `VersionFiles.updateFile` patches version files with format-preserving minimal edits (jsonc-effect `modify` + `applyEdits`), so bytes outside the edited value are untouched and JSONC survives; never reintroduce a `JSON.parse`/`JSON.stringify` round-trip. Missing wildcard-free leaf properties are inserted with detected indent; wildcard paths update existing matches only.
- Changelog rendering: release lines carry NO commit-link prefixes (git history is the reference — do not re-add them), dependency tables emit their own `### Dependencies` heading, and changeset-less releases (fixed/linked co-bumps) render a `### Maintenance` note via `deriveMaintenanceReason` + `MaintenanceNotePlugin` (parameterized per version block by `ReleasePlanner`, deliberately not a preset member). `ChangelogTransformer` runs the full `SilkChangesetTransformPreset`.
- `Lint` handlers have TWO entry points — the lint-staged `create()` command and the corresponding `savvy lint fmt <name>` subcommand — so any formatting step must be a public static both call, never inlined in one. `Lint.PnpmWorkspace.formatContent` is the worked example: `@effected/yaml` (`quoteStyle: "double"` + `indentSequences: true`) now emits the repo's byte format directly, so there is no Prettier post-process. `Lint.Yaml` runs on `@effected/yaml` too as of 0.8.0 (effected#127 landed), so Prettier and `yaml-lint` are gone from the package entirely. Its statics are SYNC — the engine is a pure IO-free tier — and `validateFile` gates on `Yaml.parseAllResult`, so a multi-document file whose LATER document is invalid is rejected rather than silently accepted. There is no config-file tier: the removed `.yaml-lint.json` discovery never resolved, and formatting is configured in code via `YamlOptions.format`.
- `Commitlint`'s `silk/body-no-markdown` rule detects bold via the asterisk form only (`**text**`), so `__SNAKE_CASE__` identifiers are not flagged. `silk/body-prose-only` exists but `createConfig` never enables it, so dash bullets are legal — check the preset before claiming a rule is enforced. `verbosity`'s exported `VERBOSITY_LINE_THRESHOLD`/`VERBOSITY_WORD_THRESHOLD` (12/150) encode the squash-merge brevity shape the plugin's `commit-create` skill teaches; move the two together. `closes-trailer`'s `hasClosingTrailer` scans the whole reference list, so one comma-joined `Closes #a, #b` line matches every id.
- `SilkPublishability.detect(pkgName, raw, binding)` resolves publish targets from the bundler's `dist/prod/targets.json` binding (Record-map `publishConfig.targets` form); public API `readTargetsBinding` + types `TargetsBinding`/`TargetBinding`/`TargetGroupBinding`.
- `SilkWorkspaceAnalyzer` is the composite workspace service (four layer deps). The shared husky-hook shells are DATA now: `SavvySections` (`SavvyBaseSection`/`SavvyHooksSection`/`savvyToolSection`) defines them and the kit's `ManagedSection` engine renders them; `SectionId` keys uppercase, so keep the marker-compat guard when adding a section.
- The kit owns the mechanisms this package used to — do NOT re-add them here, and read the design doc's migration table before hunting a service a stale note mentions: `VersioningStrategy`/`TagStyle`/`ReleaseTag` → `@effected/workspaces` (value classes; `classify` is pure and total, so there is no error to catch), `ToolDiscovery`/`Tool`/`Run` → `@effected/commands` (set env with `Run.extendEnv`, never bare `setEnv`), `ManagedSection`/`Section`/`CommentStyle` → `@effected/templates`.
- `src/index.ts` re-exports NOTHING from the kit: consumers import kit surfaces from `@effected/*` directly, so one type never gets two import paths.
- Result types are Effect `Schema` as the single source of truth, with derived interfaces.
- All Effect code uses class-based `Context.Service` (each with a companion `*Shape` interface), `Schema.Class`/`Schema.TaggedClass`, `Data.TaggedError`.
