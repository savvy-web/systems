# @savvy-web/silk-effects

Shared Effect library for the Silk Suite, and the home of the dev-tooling business logic consumed by `cli`, `mcp`, and `silk`. Single root export, dual-format ESM+CJS.

## Key surface

- One entry point (`.`) exporting four namespaces — `Changesets`, `Commitlint`, `Lint`, `Turbo` — plus standalone services, schemas, and tagged errors.
- `Turbo` is a read-only Turborepo inspection namespace: `TurboInspector` service + `TurboDigest` pure transforms (`diagnoseCache`/`taskGraph`/`affected`), all `--dry`, never executes tasks.
- `Changesets` includes `ConfigInspector`, `BranchAnalyzer`, `ChangesetLinter`, `ReleasePlanner` (`plan`/`preview`/`apply` driving the changesets v3 engine directly — v3 prereleases, no v1 packages adapter; `apply` does native version bumping, dry-run-aware, with a `changelogModules` option mapping changelog ids to module paths for no-`node_modules` callers), and `DepsRegen` (`plan`/`execute` split owning dependency-changeset orchestration; snapshots both diff sides via `workspaces-effect`'s `PointInTimeWorkspace`, resolving `catalog:`/`workspace:` per ref BEFORE diffing so equal-resolved rows are suppressed, and drops `devDependency` rows). Gating is "versionable minus ignored" — a package is in scope when `publishable OR privatePackages.version` AND not on the changeset ignore list (ignore wins over `--package`). A pure dependency changeset is only ever deleted when its package is BOTH in scope AND actually rewritten this run (present in `toWrite`) AND the file was authored on this branch rather than already committed at the merge-base ref (`gitListChangesetFilesAtRef`) — either gap previously deleted a still-relevant release note with nothing recreated (#258). `plan()` refreshes `ConfigInspector` and `ChangesetConfig` up front (both hold never-self-expiring per-root caches) so a long-lived host — the `savvy-mcp` server holds one `DepsRegen` for its whole process — sees `.changeset/config.json` edits made between calls (#229). File I/O runs through `@effect/platform` `FileSystem` (`ChangesetIOError`). `DepsRegenLive` requires `PointInTimeWorkspace | WorkspaceDiscovery | PublishabilityDetector | ChangesetConfig | ConfigInspector | FileSystem`; `DepsRegenDefault` is the batteries-included layer supplying silk's opinionated defaults (needs only a `CommandExecutor`-capable platform layer).
- `ChangesetLinter.validateContent` now enforces the dependency-table format (CSH005) via the remark `DependencyTableFormatRule`; prose `## Dependencies` sections are rejected.
- `VersionFiles.updateFile` patches version files with format-preserving minimal edits (jsonc-effect `modify` + `applyEdits`) — bytes outside the edited value are untouched and JSONC (comments, trailing commas) works end-to-end; never reintroduce a `JSON.parse`/`JSON.stringify` round-trip. Missing wildcard-free leaf properties are inserted with detected indent; wildcard paths update existing matches only.
- Changelog rendering: release lines carry NO commit-link prefixes (git history is the reference — do not re-add them), dependency tables emit their own `### Dependencies` heading, and changeset-less releases (fixed/linked co-bumps) render a `### Maintenance` note via `deriveMaintenanceReason` + `MaintenanceNotePlugin` (parameterized per version block by `ReleasePlanner`, deliberately not a preset member). `ChangelogTransformer` runs the full `SilkChangesetTransformPreset`.
- `Lint` handlers have TWO entry points — the lint-staged `create()` command and the corresponding `savvy lint fmt <name>` subcommand — so any formatting step must be a public static both call, never inlined in one. `Lint.PnpmWorkspace.formatContent` is the worked example: `@effected/yaml` emits unindented sequences and single-quoted scalars, and the Prettier pass that normalizes them back to the repo's byte format is part of the format, not a caller's concern.
- `Commitlint`'s `silk/body-no-markdown` rule detects bold via the asterisk form only (`**text**`), so `__SNAKE_CASE__` identifiers are not flagged.
- `SilkPublishability.detect(pkgName, raw, binding)` resolves publish targets from the bundler's `dist/prod/targets.json` binding (Record-map `publishConfig.targets` form); public API `readTargetsBinding` + types `TargetsBinding`/`TargetBinding`/`TargetGroupBinding`.
- `SilkWorkspaceAnalyzer` is the composite workspace service; `ManagedSection` drives the shared husky-hook shells.
- Result types are Effect `Schema` as the single source of truth, with derived interfaces.
- All Effect code uses class-based `Context.Tag`, `Schema.Class`/`Schema.TaggedClass`, `Data.TaggedError`.
