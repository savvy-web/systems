# @savvy-web/mcp

`@savvy-web/mcp` is the spawnable `savvy-mcp` server — a tools-only MCP server (not a discovery host) exposing Silk tooling over silk-effects, Effect-native on `effect/unstable/ai`'s `McpServer` (no MCP SDK, no zod). No resource/corpus layer. An L3 front end: `@savvy-web/silk` carries its bin as a shim over `./main`. Built via `@savvy-web/bundler`.

## Key surface

- Tools (ten): seven read-only — `workspace_info` (structured workspace analysis: linked/fixed package groups + resolved registry targets), `turbo_inspect` (mode cache|graph|affected over `turbo --dry`), `changeset_inspect` (mode branch|config|classify), `changeset_validate` (validates `.changeset/` files), `changeset_preview` (non-destructive release render over `Changesets.ReleasePlanner.preview`), `changeset_deps_detect` (detects dependency drift over `Changesets.DepsRegen`), `repos_inspect` (mode status|config|drift|gitmodules over `Repos.ReposManager`/`Repos.ReposConfigStore`/`Repos.ReposDrift`; markdown escapes every repo-derived string since vendored-repo content is untrusted input) — plus three mutating tools, the sanctioned exceptions to the read-only convention: `biome_check` (runs Biome with `--reporter=gitlab`, mode check|lint, `write`/`unsafe` to apply fixes), `changeset_deps_regen` (regenerates dependency changesets over `Changesets.DepsRegen`), and `repos_manage` (action sync|pin|add|note|remove|rename|restore|deregister over `Repos.ReposManager`; flat wire args decode into an internal `Schema.TaggedStruct` request union that names the missing field per action on failure; the pin markdown surfaces `commitMessage` and `staleNoteIds` as the review/commit cue; `deregister` clears a stale `submodule.<section>` local-config registration — the drift report's orphan `localRegistrationDivergence` — and its markdown says nothing is staged, since local config is unversioned).
- `repos_manage` `sync`/`add`/`pin`/`remove`/`rename`/`restore` are also where the vendored-tree boundary is applied: `ReposManager` brackets their git mutations in `Repos.ReposLockdown` and leaves each vendored WORKTREE — not its gitdir — OS-level read-only (files `0444`, dirs `0555`), which is why `runtime.ts` provides `Repos.ReposLockdown.layer` to `ReposManager.layer` and `Repos.ReposLockdownError` is in the tool's error union. The silk plugin's guards are early warning in front of that boundary, not the boundary; `repos_inspect` is unaffected, since reading a locked tree needs no write permission. `repos_inspect` `drift` reconciles FIVE authorities (the fifth is the superproject's local git config).
- Three `repos_manage` wire details are load-bearing, since the tool description IS the agent's only instruction: `add` accepts an `orientation` object and the `remove` markdown echoes `removedEntry.orientation` as a JSON block, because `add` resurrects nothing and remove-then-re-add is the standing remedy; `restore` renders its "RESTORE DID NOT FULLY SUCCEED" section only when `stillDirty` is non-empty, so the heading never becomes background noise.
- Depends only on `@savvy-web/silk-effects` within the repo; must NOT import `@savvy-web/cli` or `@savvy-web/silk` (L3 peers never reference each other). Kit surfaces (`ToolDiscovery` from `@effected/commands`, `Workspaces`) are imported directly.
- Entry chain: `bin.ts` → `main.ts` (the `./main` subpath: crash guards registered BEFORE any dynamic import of the server graph; `Logger.LogToStderr` keeps stdout pure JSON-RPC; a `runMain` `teardown` maps success-or-interrupts-only to exit 0, so stdin EOF is a clean disconnect, not 130) → `server.ts` (`ServerLayer(cwd)`: `registerSilkToolkit` over the public `McpServer.addTool`, a mirror of rc.115's `registerToolkit` except `content[0].text` is the tool's `SilkMarkdown` projection and `structuredContent` the untouched result; on `McpServer.layerStdio` with `protocols` newest-first — never reduce it to one) → `toolkit.ts` (`SilkToolkit`, `ToolsLayer(cwd)`) → `tools/*.ts` (each: a `*Params` schema, a `Tool.make` value with an explicit `dependencies` array — omit it and the handler fails `HandlersFrom` — and a `handle*` handler). `src/index.ts` never exports `main`. Re-check the `server.ts` header's gotchas and the mirror's three deviations on every rc bump.
- Errors (`errors.ts`): `McpToolError = WorkspaceNotFound | InvalidArgument | EngineError | BiomeUnavailable | BiomeFailed`, `Schema.TaggedError`s with `message` + `remediation`. A typed failure reaches the wire as `isError` text only (no `structuredContent`), so each `message` is composed at construction via `composeRemediatedMessage`, echoed caller values pass through `truncateEchoed`, and `mapEngineError` is the engine-to-wire mapping every handler applies.
- The runtime (`runtime.ts`, `makeSilkRuntimeLayer(cwd)`) is built once per process: the kit graph is `Workspaces.layerWithGitAndConfigDependenciesSubprocess({ cwd })` — `Workspaces.layerWithGit`'s service set with config-dependency hook replay in catalog assembly, so hook-injected catalogs resolve to their declared ranges in `changeset_deps_detect`/`changeset_deps_regen` diffs instead of concrete lockfile versions (#539); `ToolDiscovery.layer` over `Workspaces.localExecLayer({ cwd })` gives ONE probe cache for the server's whole lifetime, and the same lifetime holds one `DepsRegen`/`ConfigInspector` — which is why config caches are refreshed per call rather than per layer build (#229).
- Test tiers: `__test__/*.test.ts` run in-process — `server.test.ts` drives the real `ServerLayer` over `Stdio.layerTest` (`__test__/utils/harness.ts`) and is the drift alarm for the custom registration; `__test__/e2e/*.e2e.test.ts` spawn the built `dist/dev/pkg/bin/savvy-mcp.js` and assert a well-formed handshake, EMPTY stderr, and exit 0 on stdin close. Closing stdin right after a `tools/call` drops the answer and still exits 0 — read the response first.
- NO `peerDependencies` block: the Effect closure is sealed as regular `dependencies` (same posture as cli and tsdown-plugins, #228). When adding a new `@effect/*` dep, declare its required peers as regular deps too.
- Load-bearing dependencies (systems#631): the `dependencies` block lists `@effected/commands`, `@effected/git`, `@effected/workspaces`, and `effect` because they satisfy `@savvy-web/silk-effects`' `peerDependencies` — that need holds independently of whether `src/` also imports each directly, so none may be dropped as "unused" from a lint pass: removing one breaks installs at install time.
