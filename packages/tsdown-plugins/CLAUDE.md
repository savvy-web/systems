# @savvy-web/tsdown-plugins

`@savvy-web/tsdown-plugins` is the interface-only tsdown/rolldown plugin pack holding every build behavior that `@savvy-web/bundler` orchestrates. Authored against rolldown's `Plugin` type only (type-only); `tsdown` is a declared runtime dependency resolved at the two dynamic-import sites (`buildTargetGroups`, `runExeBuild`) — still no tsdown peer.

## Key surface

- Entry detection; manifest transforms (`emitManifest`, `defaultManifestTransform`, the `"./package.json"` self-export inject); `resolveManifest` over `@effected/workspaces`' one-shot `Workspaces.resolveManifest` (re-discovers the workspace root from `process.cwd()`; assembles catalogs durably — inline + config-dependency hook-replay + lockfile — so no `.pnpm-workspace-state-v1.json` is needed). Rejects with `ManifestDecodeError`, `UnresolvedDependencyError`, `CatalogAssemblyError`, or `DependencyResolutionError` — all four exported (kit re-exports).
- Zero-config ambient `.d.ts` exports (`src/entry/ambient-dts.ts`): a types-only export whose source is a hand-authored declaration (bare `.d.ts` string or `{ types: "*.d.ts" }`) is classified (`classifyDtsExport`/`extractAmbientDts`), rewritten in the published manifest to a KEY-derived `{ types: "./<key>.d.ts" }` path (`transformExports`), and copied verbatim into every target dir (`copyAmbientDts` in `src/build/sync-public.ts`) — no custom `transform`, no post-build step. The copy itself runs INSIDE `buildTargetGroups` (alongside `copyPublicDir`, once per group), not in the bundler's `runBuild`, so every build path — including the `bundler`/`tsdown-plugins` self-hosting escape hatches that call `buildTargetGroups` directly — copies its ambient exports; `runBuild` still does the early `extractAmbientDts`/`assertNoEntryCollisions` fast-fail validation before any build branch.
- `buildTargetGroups`: name-aware two-pass per-TargetGroup loop (per-module JS pass + bundled `emitDtsOnly` dts pass — `bin/` executable entries are dropped from the dts pass, so bin-only partitions skip it) plus a prod-only per-module declarations pass for API Extractor diagnostics (`emitDeclarations: true`), configurable `BuildFormat`, per-entry `overrides` (`EntryOverride`/`DualExports`), and `bundle`/`bundleNodeModules`/`dtsExternals` bundling posture (`bundleNodeModules` bundles both formats into one npm-pack-safe self-contained file; do NOT reintroduce tsdown's deprecated `deps.skipNodeModulesBundle` — tsdown warns on the option's PRESENCE regardless of value and only branches on it truthily, so `bundleNodeModules` contributes no `deps` flag and the `bundledPackages`-without-`bundleNodeModules` dts branch uses `deps.neverBundle: true`); `copyPublicDir` (`src/build/sync-public.ts`) runs once per group after all passes (flattens `public/<path>` → `<pkg>/<path>`, byte-comparison collision guard), followed by the ambient `.d.ts` copy.
- `src/meta/`: `runMetaPass` (`run-pass.ts`) — the single meta orchestrator shared by `runBuild` and both self-hosting escape hatches — wrapping `generateMeta` over `@microsoft/api-extractor` + multi-entry api-model merge, the portable-tsconfig resolver (`tsconfig-resolver.ts` — extends-merging AND enum-to-string conversion are both `@effected/tsconfig-json`'s `TsconfigLoaderSync` + `PortableTsconfig`, with no `typescript` import of its own; do not reintroduce a hand-rolled enum-converting resolver). `typescript` stays a runtime dep, direct-pinned `^6.0.3` — NOT `catalog:silk` — because TS 7.0 ships no stable compiler API until 7.1 and a peer-resolved TS7 flips rolldown-plugin-dts onto its broken "tsgo" dts generator; do not move it back to the catalog before 7.1. Its ONLY remaining importers are the two `src/dts/` AST files (`relative-imports.ts`, `reexport-stub.ts`), plus api-extractor's own resolution; `tsdown` is a declared dependency precisely so its dts passes resolve this pinned TS6, and `deriveDtsPassOptions`/`deriveDeclarationsPassOptions` pin `generator: "tsc"` explicitly; `deriveExportPaths`/`applySubdirMetaEntries` are exported alongside it. The same pass emits the `tsdoctor.json` sidecar (spec 1, encoded through `@tsdoctor/manifest`) into each prod group's `meta/` and `meta.localPaths`: `tsdoctor-config.ts` (`MetaOptions.tsdoctor` = `TsdoctorMetaOptions`, the CONFIG tier, plus `OgImageInfo`), `tsdoctor-source.ts` (`loadTsdoctorSources` — the leaf `<pkg>/tsdoctor.json` and project `<workspaceRoot>/tsdoctor.json` tiers; a present-but-invalid file is `TsdoctorSourceError`; a discovery failure is surfaced as `discoveryFailure`, never swallowed), `tsdoctor-manifest.ts` (pure `composeTsdoctorManifest`: config > leaf > project per field, `project` kept NESTED, registries from the group's `targets.json` via `registriesFromTargets`/`githubOwnerRepo`, never an `sbom`), `og-image.ts` (`writeGeneratedOgImage` for `openGraph.generate` → `meta/og/<unscoped>.<png|jpg|webp>`, `OgGenerateError` otherwise), and `TsdoctorEmitError` (`src/errors.ts`) when the sidecar itself fails to encode or write. All three are `Data.TaggedError`s; `runMetaPass` routes them to the collector as `source: "meta"` (`tsdoctor-source-invalid`, `og-generate-failed`, `tsdoctor-emit-failed`, plus the non-fatal warning `tsdoctor-workspace-discovery-failed`). Stale `tsdoctor.json`/`og/` from a previous build are removed from the meta dir and every `localPaths` copy on each run.
- `src/targets/`: `resolveTargets`/`writeTargetsBinding` deriving byte-variant groups from `publishConfig.targets`; throws `ConfigValidationError`.
- `src/jsx/` (tsconfig JSX runtime resolution), `src/exe/` (`normalizeExeOptions`/`runExeBuild`).
- `src/report/`: `BuildCollector`/`BuildCollectorTag`, `createTsdownLogger`, `buildMetricsPlugin`, and the `BuildReport` schema (`passes: PassReport[]` with `EmittedFile` + `DiagnosticEntry[]`, whose `source` is `tsdown | rolldown | api-extractor | meta` — `meta` is the sidecar pass's own diagnostics) that the bundler renders into one unified log. API Extractor analyzer messages (`ae-forgotten-export`, `ae-missing-release-tag`, `tsdoc-*`) surface as warnings; forgotten exports escalate to a hard build error under CI. `src/report/issues-artifact.ts` is the persisted counterpart — `flattenIssues`/`writeIssuesArtifact` (re-exported) write a deduped `dist/<target>/issues.json` on every dev/prod build and on every terminal path, success AND failure, via an atomic tmp+rename (`ae-*`/`tsdoc-*` stay prod-only). It is the structured surface the tsdoctor agent and tsdoc skill consume, so its contract is load-bearing: absence means not-built, and a PRESENT artifact must be read `buildOk` FIRST — never `errors.length` — because a crashed build's empty diagnostic buckets are byte-identical to a clean gate. `failure` (`{ name?, message }`) carries the terminal error when `buildOk` is false; a missing `buildOk` is unknown, not a pass. `flattenIssues` defaults it to `true`, so any caller that writes on a failure path MUST pass `buildOk: false` explicitly.
- Warning suppression must live in these report seams, never in tsdown config: tsdown's own `suppressWarnings` option is unreachable here because `createLogger` returns early when a `customLogger` is supplied, and this builder always supplies one when a collector exists. `buildMetricsPlugin`'s optional `suppressMixedExports` parameter routes rolldown's `MIXED_EXPORTS` warning into the report's `suppressed` bucket; `buildTargetGroups` sets it for exactly the passes that install `cjsDefaultInterop()`.
- Rolldown transforms: `nodeBuiltinDefaultInterop` (cjs default-import interop), `removeDeclarationMaps`, `cjsDefaultInterop`.
- `ConfigValidator`/`ConfigValidator.layer` rule set.
- Ships NO tsconfig preset and has no `ecma.json` sync test: its own `tsconfig.json` extends the bundler's `public/tsconfig/ecma.json` by relative path. Only `rspress-builder` keeps a synced copy (guarded by its `__test__/ecma-sync.test.ts`).
- Effect v4 (`effect`/`@effect/platform-node` on `catalog:effect`), in line with the rest of the repo. The sealed-Effect-closure posture (#228) is GONE: v4's peer closure is just `effect`, so the `@effect/cluster|experimental|rpc|sql|workflow|platform` deps that existed only to seal it were removed. Still NO `peerDependencies` block. Services are `Context.Service` classes (not v3 `Context.Tag`).
- Kit deps (`@effected/*`, registry-resolved unless a dogfood round is open — see the root `CLAUDE.md` "Dogfooding @effected" section): `@effected/workspaces` + `@effected/npm` (catalog/workspace resolution, `DependencySpecifier` predicates, `WorkspaceDiscovery.listPackages`) and `@effected/tsconfig-json`. JSON Schema comes from core `effect`'s `JsonSchema`.
- Self-hosts (bootstraps via `tsx`, its `savvy.build.ts` calling `runMetaPass` directly); versions independently from the bundler. On prod its self-build emits its own api-model, `dist/prod/issues.json`, and is API-Extractor validated, so tsdown-plugins now publishes into the mcp + website corpus.
