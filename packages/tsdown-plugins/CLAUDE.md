# @savvy-web/tsdown-plugins

`@savvy-web/tsdown-plugins` is the interface-only tsdown/rolldown plugin pack holding every build behavior that `@savvy-web/bundler` orchestrates. Authored against rolldown's `Plugin` type only (type-only); `tsdown` is a declared runtime dependency resolved at the two dynamic-import sites (`buildTargetGroups`, `runExeBuild`) — still no tsdown peer.

## Key surface

- Entry detection; manifest transforms (`emitManifest`, `defaultManifestTransform`, the `"./package.json"` self-export inject); `resolveManifest` over `@effected/workspaces`' one-shot `Workspaces.resolveManifest` (re-discovers the workspace root from `process.cwd()`; assembles catalogs durably — inline + config-dependency hook-replay + lockfile — so no `.pnpm-workspace-state-v1.json` is needed). Rejects with `ManifestDecodeError`, `UnresolvedDependencyError`, `CatalogAssemblyError`, or `DependencyResolutionError` — all four exported (kit re-exports; `UnresolvedDependencyError` is the former `CatalogResolutionError`).
- Zero-config ambient `.d.ts` exports (`src/entry/ambient-dts.ts`): a types-only export whose source is a hand-authored declaration (bare `.d.ts` string or `{ types: "*.d.ts" }`) is classified (`classifyDtsExport`/`extractAmbientDts`), rewritten in the published manifest to a KEY-derived `{ types: "./<key>.d.ts" }` path (`transformExports`), and copied verbatim into every target dir (`copyAmbientDts` in `src/build/sync-public.ts`) — no custom `transform`, no post-build step. `src/dts/relative-imports.ts` (`findRelativeSpecifiers`) and `assertNoEntryCollisions`/`mixedDtsExportError` guard collisions.
- `buildTargetGroups`: name-aware two-pass per-TargetGroup loop (per-module JS pass + bundled `emitDtsOnly` dts pass — `bin/` executable entries are dropped from the dts pass, so bin-only partitions skip it) plus a prod-only per-module declarations pass for API Extractor diagnostics (`emitDeclarations: true`), configurable `BuildFormat`, per-entry `overrides` (`EntryOverride`/`DualExports`), and `bundle`/`bundleNodeModules`/`dtsExternals` bundling posture (`bundleNodeModules` flips the JS pass's `unbundle` off, so both formats bundle into one npm-pack-safe self-contained file — `npm pack` strips the `node_modules` dirs preserveModules would emit); `copyPublicDir` (`src/build/sync-public.ts`) runs once per group after all passes — flattens `public/<path>` → `<pkg>/<path>`, additive with a byte-comparison collision guard (throws `ConfigValidationError` on differing-byte destination conflict).
- `src/meta/`: `runMetaPass` (`run-pass.ts`) — the single meta-generation orchestrator called by the front-door `runBuild` AND by both self-hosting escape hatches — wrapping `generateMeta` over `@microsoft/api-extractor` + multi-entry api-model merge, the portable-tsconfig resolver (`tsconfig-resolver.ts` — extends-merging is `@effected/tsconfig-json`'s `TsconfigLoaderSync` + `PortableTsconfig`; `typescript` supplies only the compiler-option enums). `typescript` stays a runtime dep, direct-pinned `^6.0.3` — NOT `catalog:silk` — because TS 7.0 ships no stable compiler API until 7.1 and a peer-resolved TS7 flips rolldown-plugin-dts onto its broken "tsgo" dts generator; do not move it back to the catalog before 7.1. Its remaining importers are the two `src/dts/` AST files (`relative-imports.ts`, `reexport-stub.ts`) and this resolver's enums, plus api-extractor's own resolution; `tsdown` is a declared dependency precisely so its dts passes resolve this pinned TS6, and `deriveDtsPassOptions`/`deriveDeclarationsPassOptions` pin `generator: "tsc"` explicitly; `deriveExportPaths`/`applySubdirMetaEntries` (moved here from the bundler) are exported alongside it.
- `src/targets/`: `resolveTargets`/`writeTargetsBinding` deriving byte-variant groups from `publishConfig.targets`; throws `ConfigValidationError`.
- `src/jsx/` (tsconfig JSX runtime resolution), `src/exe/` (`normalizeExeOptions`/`runExeBuild`).
- `src/report/`: `BuildCollector`/`BuildCollectorTag`, `createTsdownLogger`, `buildMetricsPlugin`, and the `BuildReport` schema (`passes: PassReport[]` with `EmittedFile` + `DiagnosticEntry[]`) that the bundler renders into one unified log. API Extractor analyzer messages (`ae-forgotten-export`, `ae-missing-release-tag`, `tsdoc-*`) surface as warnings; forgotten exports escalate to a hard build error under CI. `src/report/issues-artifact.ts` is the persisted counterpart — `flattenIssues`/`writeIssuesArtifact` (re-exported) write a deduped `dist/<target>/issues.json` on every build (always written: absent means not-built, empty means clean; `ae-*`/`tsdoc-*` are prod-only), the structured surface the tsdoctor agent and tsdoc skill consume.
- Rolldown transforms: `nodeBuiltinDefaultInterop` (cjs default-import interop), `removeDeclarationMaps`, `cjsDefaultInterop`.
- `ConfigValidator`/`ConfigValidatorLive` rule set; ships a synced local `ecma.json` copy guarded by a unit test.
- Effect v4 (`effect`/`@effect/platform-node` on `catalog:effect`) — ahead of the rest of the repo, which is still v3 on `catalog:silk`. The sealed-Effect-closure posture (#228) is GONE: v4's peer closure is just `effect`, so the `@effect/cluster|experimental|rpc|sql|workflow|platform` deps that existed only to seal it were removed. Still NO `peerDependencies` block. Services are `Context.Service` classes (not v3 `Context.Tag`).
- Kit deps (`@effected/*`, dogfooded from local `file:` overrides — see the root `CLAUDE.md` "Dogfooding @effected" section): `@effected/workspaces` + `@effected/npm` (catalog/workspace resolution, `DependencySpecifier` predicates, `WorkspaceDiscovery.listPackages` — replacing `workspaces-effect` and `@manypkg/get-packages`) and `@effected/tsconfig-json`. JSON Schema comes from core `effect`'s `JsonSchema` (was `json-schema-effect`).
- Self-hosts (bootstraps via `tsx`, its `savvy.build.ts` calling `runMetaPass` directly); versions independently from the bundler. On prod its self-build emits its own api-model, `dist/prod/issues.json`, and is API-Extractor validated, so tsdown-plugins now publishes into the mcp + website corpus.
