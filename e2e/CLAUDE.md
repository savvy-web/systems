# @e2e harness

`e2e/*` holds PRIVATE, never-published harness packages that exercise BUILT artifacts. Only `@e2e/silk` remains: it has no single owning package. Every other e2e suite lives in its package under `packages/<pkg>/__test__/e2e/`: cli's `bin` and `regen-catalog` suites, mcp's `server-lifecycle`, silk's carrier `bins`, and pnpm-plugin-silk's `pnpmfile-contract`. Those suites reach the artifact BY PATH (`../../dist/prod/npm/pkg/...`), never by a bare self-import — inside its own package a bare `@savvy-web/<pkg>` import self-references the source manifest's `exports`, which point at `src/`. Workspace links resolve to source, so the root `vitest.setup.ts` builds only `--filter '@savvy-web/silk...' --filter @savvy-web/pnpm-plugin-silk` before a run — silk's closure plus pnpm-plugin-silk for its pnpmfile contract. A built bin in the workspace still imports its siblings from source, so a suite that spawns one passes `NODE_OPTIONS=--import=<absolute tsx file URL>` — a bare `--import=tsx` resolves against the child's cwd and fails. `e2e/*` stays in the `pnpm-workspace.yaml` `packages:` glob, discovered by `AgentPlugin.discover()`, and runs in the normal `pnpm test` gate — no separate project or CI job.

`@e2e/silk` proves the carrier pattern from OUTSIDE the workspace, on the kit's `PackedInstall` (`@effected/workspaces/testing`). `packed-install.e2e.test.ts` makes ONE `PackedInstallOptions` object (`carrier: "@savvy-web/silk"`, `closure: "auto"`, `managers: ["pnpm", "npm", "yarn", "bun"]`, `bins: ["savvy", "savvy-mcp"]`, `allowSharedBins: true`, `require: "any"`). `PackedInstall.closure` plans the closure at module evaluation (silk plus cli, mcp, changelog, silk-effects, silk-core). `PackedInstall.run` packs each package from its default `dist/prod/npm/pkg` — the published artifact, whose manifest `effected package build` has already resolved from `workspace:*`/`catalog:` to concrete versions — installs only the silk tarball into one scratch consumer per available manager, and steers the companions to their tarballs through each manager's own override field. A manager missing from PATH is skipped and logged, never a failure. Yarn is always the harness's own Berry: `@e2e/silk` declares `@yarnpkg/cli-dist` (`catalog:test`) and the test puts its own `node_modules/.bin` first on the managers' PATH. The suite runs from the root, whose PATH has no `yarn`, and a GitHub runner's preinstalled Yarn Classic is unsupported. Per consumer it asserts: no `.npmrc`, hoist pattern, config dependency or `pnpm-plugin-silk`; silk's exact pins and `bin` map; the `.bin` slot owner (`binProvenance`, silk or the front end sharing the name); that what a user types (`runBin`, `McpProbe` over `consumer.command`) runs; and that the carrier's OWN shims (`runCarrierBin`, and `McpProbe` over `carrierCommand`) print the `via @savvy-web/silk <version>` suffix on `--version` and `serverInfo.version`, with empty stderr and exit 0, on EVERY manager. `allowSharedBins: true` is deliberate: cli/mcp keep their own `savvy`/`savvy-mcp` bins, so the slot a user types may belong to a front end (npm, bun) and carry no suffix. The test and vitest timeouts come from `PackedInstall.timeoutBudget`, never a hand-picked constant. It needs the network for `effect` and the `@effected` kit. The in-repo half (the same bins straight out of `packages/silk/dist/prod/npm/pkg/bin`, driven through `Run.collect` and `McpProbe`) lives in `packages/silk/__test__/e2e/bins.e2e.test.ts`.

## Core rule

e2e tests must NOT resolve `catalog:`/`workspace:` against the host repo. They spawn the built tool (for example the built `savvy` bin) or import the built artifact with `cwd` = a fixture repo, so `workspaces-effect`'s `CatalogResolver` (which reads `process.cwd()`) roots at the fixture, not the host. Catalog/workspace resolution coverage lives here precisely because it would otherwise see the host's real catalogs.
→ `@../okf/conventions/e2e-isolation.md`
Load before writing or reviewing an e2e test that resolves catalogs or workspace packages.

## Conventions

- **Fixtures** live under `packages/<pkg>/__test__/e2e/fixtures/<name>/`. Each fixture that triggers resolution carries its OWN `pnpm-workspace.yaml` (inline catalogs / sibling stubs) so the resolver root-walk stops there. Fixtures are test data, NOT workspace members (biome-ignored).
- **Adding a subprocess test:** build the spawn env from `process.env` minus `NODE_V8_COVERAGE` (as `packages/cli/__test__/e2e/regen-catalog.e2e.test.ts` does) plus the absolute-URL tsx `NODE_OPTIONS`. Stripping `NODE_V8_COVERAGE` keeps subprocesses from racing vitest's V8 coverage collection. Without it, `pnpm test` intermittently exits 1 on a coverage ENOENT even though the tests pass. `@e2e/silk` has no helpers file: a packed-install consumer's bins run through `PackedInstall`'s `consumer.runBin`/`runCarrierBin`/`command`/`carrierCommand`, which build the scrubbed environment themselves (layer overrides such as `NO_COLOR` or an unset `CLAUDE_PROJECT_DIR` through their `env` option).
- **In-process unit tests** that can't subprocess but still trigger host resolution use the hermetic pattern: `chdir` into a temp dir with its own empty `pnpm-workspace.yaml`, restore the previous cwd in `finally`.
